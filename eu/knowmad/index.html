3// El Corte Inglés — katalogo domeinua.
4// Hemen Kafka CVko lerro bat izateari utzi zion: prezio aldaketa bat
5// hedatzen da zerbitzu batek besteari deitu gabe.
6@Component
7@Slf4j
8@RequiredArgsConstructor
9public class KatalogoEventConsumer {
10
11    private final IkasitakoaRepository ikasitakoak;
12
13    @KafkaListener(topics = "katalogoa.produktua.eguneratua",
14                   groupId = "katalogo-service")
15    public void onGertaera(KatalogoEvent gertaera, Acknowledgment ack) {
16
17        log.info("{}(r)en gertaera {} SKUrako",
18                 gertaera.bezeroa(), gertaera.sku());
19        try {
20            ikasitakoak.saveAll(Ikasitakoa.atera(gertaera));
21            ack.acknowledge();          // offsetaren eskuzko commita
22        } catch (Exception e) {
23            log.error("Errorea {} prozesatzean → DLQ", gertaera.sku(), e);
24            throw e;
25        }
26    }
27}

# Knowmad Mood · 2022 aza – 2025 ira

Hiru urte aholkularitzan bi bezerorentzat: BeeDigital primero (enpresen kokapena interneten, AWSen gainean) eta El Corte Inglés gero (katalogo domeinua, MongoDB eta bolumen handia).

Hemen mikrozerbitzuek "erabili behar dena" izateari utzi zioten eta benetan ulertzen nuen zerbait bihurtu ziren: zergatik banatzen diren, noiz merezi duen, eta bat erortzen denean zer gertatzen den. Hemen bihurtu zen Kafka CVko lerro bat izatetik eguneroko tresna izatera.

Kasu zehatza: katalogoko produktu batean egindako edozein aldaketak —prezio berri bat, alta bat— erakusten duten zerbitzu guztietara iritsi behar du, eta domeinu horretan 150 inguru ziren Kafka bidez komunikatzen. Zerbitzuen arteko deiekin konpontzeak akoplatu egiten ditu, eta bat erortzen bada besteak ere arrastatzen ditu; gertaera gisa argitaratuta, kontsumitzaile bakoitzak bere erritmoan prozesatzen du, benetan amaitu duenean berresten du offseta, eta huts egiten duena bereizitako ilara batean amaitzen da.

Aurreko etapak (NTT Data) eta oraingoak (Sopra Steria) beren kapitulua dute.
